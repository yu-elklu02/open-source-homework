### 我的理解与结论

当前人工流程为：会员识别 → 权益核验 → 优惠计算 → 收银确认 → 售后反馈。

活动策划员负责规则和版本交接，CRM工程师负责系统和数据，收银员负责现场核验，客服负责投诉和反馈。主要卡点是优惠券规则解释不一致、电话等待、说明未随业务编号交接，以及接口中断或数据延迟时缺少统一处理方式。

一、主流程与节点
1. 会员识别：输入为会员手机号/会员码，系统为CRM、POS、小程序会员中心三套，账号权限独立、业务状态无统一视图（f30）。已知数据问题：手机号合并会员后旧券未迁移、会员等级更新延迟（f31）。责任人：收银员现场操作，CRM工程师维护数据。
2. 权益核验：输入为会员规则、活动版本、券使用记录、积分流水（f21）。现场做法是收银员在小程序与门店口径不一致时打电话问运营（f10），等回复期间客户在柜台等待，收银员不敢自行承诺权益。责任人：收银员发起，运营口头答复。
3. 优惠计算：依赖券使用记录与积分流水，接口可读权益与活动，但不自动合并账号或调整积分余额（f32）；试点计划每15分钟更新已授权业务状态，超一个周期标“待刷新”，不能作实时承诺（f34）。
4. 收银确认：收银员按门店口径解释并完成结账；关键说明常留在个人便签或群里再补进正式记录，未随单据交接（f14），换班复核易对不上。
5. 售后反馈：客户或下游反馈优先关联原业务编号和当时资料版本，再查交接是否完成；争议由客户服务主管受理、活动策划员核对，未经确认不承诺赔偿或结果（f54）。每周收集收银员、活动策划员、客服的误判例子与未解决问题，由会员运营经理确认改进负责人，复测8家门店99%一致率、错扣积分为零后再更新规则版本（f55）。

二、交接与责任

三、异常路径
1. 解释不一致：收银员打电话问运营（f10），但电话确认无留痕机制，事后无法回溯；需明确以哪边为准、谁拍板、是否留痕随单交接（待验证假设）。

3. 版本冲突：附两个版本给数据隐私专员，不自行合并或选较宽松条款（f24）。
4. 接口中断：继续使用带时间戳的上一份只读快照并显示“暂未更新”，重连后按业务编号去重补齐，不反复触发同一待办，现有人工流程继续运行（f35）。
5. 转人工兜底：出现退货追回无规则、资料缺依据、两版本冲突或关键系统不可用时转人工，须标注触发原因、接手人和确认时间（f44）。

四、理想流程与现场做法差异
